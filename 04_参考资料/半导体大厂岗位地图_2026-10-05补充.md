# 半导体大厂岗位地图：2026-10-05补充

> 历史职责样本：核查时间2026-10-05。下文“当前/可申请/报价”只指当时快照，本轮未重新核在招状态。仅用于对照芯片岗位能力，执行日程以规划/后续安排为准。

> 目的：按“半导体/芯片铲子行业优先、大公司优先、Linux/C/C++为主、15K+、长期积累”重新整理岗位，不把AI应用、后台、Qt界面当主线。
> 说明：官方JD用于确认职责和门槛；BOSS/猎聘/高校就业平台等用于观察薪资和招聘广度。第三方薪资不是本人offer保证。岗位状态会变化，投递前需再次打开确认。

## 1. 先给结论

你应该把“想进半导体”拆成软件岗位族，而不是只盯某一家GPU公司。

当前最值得研究的顺序：
1. **SoC Linux BSP / Linux Driver / Kernel**：最现实的转型入口之一。
2. **芯片诊断软件 / Silicon Validation Software / Development Tools**：非常值得重视，能承接C++、调试、完整项目经验。
3. **Firmware / Platform Firmware / OpenBMC / Boot**：芯片和服务器底座，硬件知识增加，但不是纯硬件设计。
4. **GPU/NPU User-mode Driver / Runtime / System Software / Profiling Tools**：长期高价值目标，先补系统基础再进入专项。
5. **CPU/GPU Platform Enablement / Performance / Virtualization**：通常更高门槛，适合作为3～5年深化方向。
6. **EDA软件研发**：Synopsys/Cadence/Siemens EDA一类，本质也是半导体“卖铲子”；C++/Linux/仿真、验证、工具开发可成为独立候选路线。

不优先：普通后台、AI应用/Agent、大模型业务、纯图像/视频算法、Qt主责、只执行固定测试脚本的测试岗。

## 2. 你的经验怎样迁移

可复用：
- 约4年软件工程、C++/Qt、通信、线程、数据库、完整项目流程。
- 设备联调、问题复现、需求理解、交付经验。
- 当前Linux二次开发、少量STM32经历。
- UI能力可用于内部诊断工具、trace/性能可视化、测试工具，但只作为加分项。

必须新增：
- Linux系统：进程/线程、虚拟内存、文件系统、网络基础、系统调用、调试。
- 内核/驱动：设备模型、Device Tree、platform driver、I2C/SPI/UART/GPIO、interrupt、DMA、power management。
- 启动链：BootROM概念、U-Boot、kernel boot、rootfs、Buildroot/Yocto。
- 硬件接口：寄存器、MMIO、总线、PCIe基础、IOMMU、cache、看datasheet/原理图。
- 工具：gdb、perf、ftrace、dmesg、strace、Git、交叉编译、基本Python/Shell。
- 中长期GPU/Runtime：queue/stream/event、host/device memory、异步DMA、同步、任务提交、trace/profiling。

### 对国外大厂的现实判断

- 下一份工作不要只盯NVIDIA/AMD/Intel，否则容易因为相关专业、英语和专项年限而“准备很久但没有中间落点”。
- 更合理的是：先在国内SoC/GPU/汽车芯片/CPU生态公司获得真实Linux BSP、driver、firmware、diagnostics责任，再冲国际大厂的system software。
- 如果出现“equivalent experience”或未强制相关专业的岗位，可以尝试；但不能把4年Qt/仪器软件直接写成4年kernel/driver经验。
- 英语会越来越重要，尤其是开源社区、datasheet、全球团队、外企面试。

## 5. EDA：新增的重要“铲子行业”候选

这条以前规划里重视不够。

### 为什么它符合你的总目标

EDA公司不是做AI应用，而是给芯片设计、验证、仿真、签核提供软件工具，是典型的半导体基础设施。
常见软件岗位：
- C/C++ R&D Software Engineer
- EDA Tool / Simulation / Verification Software
- Performance/Algorithm Engineer
- Debug/Visualization/GUI Tool（GUI只是其中一部分）
- Emulation/Prototyping Tools
- Application Engineer（偏客户技术支持，需注意出差和支持强度）

### 重点公司

- **Synopsys**：2026-09仍有上海 Software Engineering/R&D、武汉/成都IP与R&D岗位；中国多个研发城市，包括上海、武汉、南京、深圳、西安、厦门等。
- **Cadence**：后续继续核中国R&D岗位，重点看C++/Linux、仿真/验证/EDA算法，不把AE售前岗位等同纯研发。
- **Siemens EDA**：后续核C++/Linux、仿真/验证工具岗位。
- 国内EDA公司也可后续加入，例如华大九天、概伦电子、芯华章等，重点筛软件研发而非FAE/售前。

### EDA对你的优缺点

优点：
- 更接近你已有“软件工程/C++”资产，不一定要求长期板级联调。
- 行业本身直接服务芯片设计，是半导体“卖铲子”。
- 技术可深入到大型C++工程、性能、图算法/优化、仿真、工具链。

难点：
- 很多核心R&D岗位需要算法、数据结构、计算机体系结构/数字电路/EDA领域知识。
- 部分岗位偏硕士/名校/相关专业。
- Application Engineer可能客户支持较多，不一定符合你的工作边界。

**结论：EDA应加入正式候选，但目前放在“SoC Linux/驱动”和“诊断工具”之后研究，不立即替代主线。**

## 6. 15K+：市场样本怎么理解

本轮能看到的公开样本：
- 紫光展锐 Linux Kernel：约30–45K·15薪，5–10年，本科（BOSS聚合样本）。
- 紫光展锐 Android/Linux Driver：约15–25K，3–5年，本科（BOSS聚合样本）。
- 黑芝麻智能 Linux Driver Display：约20–40K或20–50K·15薪，3年以上，本科（猎聘样本）。
- 黑芝麻智能 MCU Driver：约20–40K·15薪，3年以上，本科。
- 地平线/地瓜机器人 Chip System BSP：约20–40K·15薪，1–3年，本科。
- 摩尔线程 GPU Kernel Driver：聚合样本约30–50K；GPU Firmware约20–40K/25–35K。
- 景嘉微 GPU Software：2026-09高校招聘页面20–40K/月，硕士；Embedded Software 20–30K/月，硕士。
- 兆芯 System Modeling/Performance：校招聚合样本20–28K，硕士。

这些只能说明：**半导体系统软件达到15K+的岗位客观存在，而且不少明显高于15K。**
不能说明：你现在投递就能拿到对应上限。

所以后续筛选的核心不再是“有没有15K”，而是：
1. 有没有你能在1～2个跳槽阶段够到的岗位；
2. 学历/专业筛选能不能通过；
3. 技术职责是否真实积累；
4. 工时是否符合边界。

## 7. 加班与工作强度：不要按行业一刀切

半导体软件的压力通常与项目阶段/岗位职责强相关：

相对容易出现高峰的场景：
- 新芯片bring-up；
- 流片后silicon validation；
- 量产前问题闭环；
- 大客户项目交付；
- driver/kernel严重问题；
- 跨时区全球团队release；
- firmware/board现场问题。

JD中出现以下词时要重点追问：
- customer support / on-site；
- bring-up；
- production issue / mass production；
- critical issue / escalation；
- travel；
- non-business hours support；
- fast paced；
- 能承受压力。

但不能直接推导“国产GPU=996”或“外企=955”。必须问具体团队。

面试反问固定用这几句：
1. 最近3个月团队通常几点下班？
2. 新芯片bring-up/量产阶段，一年大约有几次高峰？每次持续多久？
3. 是否有夜间on-call、周末值班、客户现场支持？
4. 这个岗位开发/调试/客户支持分别约占多少？
5. 出现硬件问题时，软件工程师负责定位到哪一层？硬件团队如何分工？



## 8. 按“下一份→中期→长期”分层，不要求一步到位

### 第一层：下一份最值得争取
优先搜索：
- Linux驱动工程师
- Linux BSP软件工程师
- Embedded Linux Engineer
- SoC Software Engineer
- Platform Software Engineer
- Firmware Engineer（偏C/SoC/boot，不是纯应用）
- Chip/System Validation Software Engineer
- Diagnostics Software Engineer
- Development Tools Engineer

目标：进入真正的芯片/SoC研发环境，开始拥有底层代码、bring-up、故障定位或诊断工具责任。工资筛选仍以税前15K目标为主，但若岗位技术非常好也必须先满足用户现有最低收入边界，不因“进芯片行业”自动接受明显降薪。

### 第二层：有1段真实专项后
- Linux Kernel Engineer
- Upstream Driver Engineer
- Platform Firmware / OpenBMC
- Silicon Validation Software
- CPU/GPU Development Tools
- System Performance Engineer
- User-mode Driver Engineer

### 第三层：长期高价值专项
- GPU Kernel Driver
- GPU/NPU Runtime
- GPU Firmware
- CPU/GPU Platform Enablement
- Virtualization / IOMMU / PCIe深度系统软件

这不是必须逐级升职的固定路线，而是用于控制学习范围：先得到第一段可验证的芯片软件责任，再决定深入哪一条。

## 9. 当前个人优先级（本轮研究后的建议，不替本人最终决定）

**优先级A：SoC Linux BSP / Driver**
- 最适合用i.MX6ULL快速做出真实作品。
- 国内公司覆盖广：晶晨、乐鑫、瑞芯微、全志、展锐、地平线、黑芝麻等。
- 与后续CPU/GPU驱动、平台软件共享大量基础。
- 风险：硬件联调和客户支持比例必须筛选。

**优先级A：芯片诊断/验证软件 / Development Tools**
- 这是本轮应新增的重要方向。
- 能利用C++、工具开发、完整项目、调试和可视化经验。
- NVIDIA GPU Development Tools、AMD IO diagnostics、Intel system software validation都证明这类岗位真实存在。
- 学习重点不是GUI，而是trace、测试API、自动化、系统行为、日志/性能/根因定位。

**优先级B：Firmware / OpenBMC / Platform Firmware**
- 长期价值明确。
- 需要补boot、UEFI/BMC/RTOS/硬件接口。
- 若岗位客户现场/夜间响应多则排除。

**优先级B：EDA软件研发**
- 很符合“半导体铲子行业+软件工程”。
- 下一轮应专门核国内外EDA公司实际C++岗位、学历要求、薪资和工时。

**优先级C：GPU/NPU Runtime / GPU Driver**
- 长期非常符合，但现在不应把它设成唯一下一份工作目标。
- 先通过BSP/driver/diagnostics建立系统底层履历，再专项补GPU。
