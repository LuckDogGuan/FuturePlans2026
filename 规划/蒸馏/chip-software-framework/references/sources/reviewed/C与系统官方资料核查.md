## 8. 官方文字资料：C 细节与调试必须读到哪里

### N01：WG14 N1570，固定 C11 草案版本

[WG14 原文 PDF](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。它是 2011-04-12 委员会草案，用于公开查证 C11 语义，不说它是最新 C 标准或已购买的 ISO 正版。周计划的 C 实验基线可固定 `-std=c11`；Linux 内核实际使用其要求的 GNU C 模式和构建系统。

| 周主题 | 具体条款 | 读后要能做什么 |
| --- | --- | --- |

### T01：GDB，固定“观察什么”

[GDB 当前手册目录](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/)核实第9章源码、第10章数据、第10.6节内存、第10.14节寄存器。[10.6 内存检查](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/Memory.html)说明 `x/nfu addr`。

- W01–W03：`break`、`next`、`step`、`print`；`x/16bx` 看字节，`x/8hx` 看 halfword；写明 GDB 的 `h` 是 2 字节、`w` 是 4 字节，不与各 ISA 的 word 名称混淆。
- W04–W07：给每个指针画对象图；在越界前暂停；对比栈/堆地址、`ptype` 和内存原始字节。记录错误发生的访问指令、地址、对象大小。
- W08：`bt`、`info registers`、`disassemble` 对齐调用栈和反汇编；遇到优化变量不可见，保留优化构建并做对应调试构建对照。
- 内核阶段：用课程的 QEMU GDB stub 跟踪 trap/IRQ；JTAG、真实 MMIO 副作用和板端故障另外验收。调试器读取具有副作用的寄存器之前查手册。

### T02：GCC Sanitizer，先宿主后交叉

[GCC 官方插桩选项](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html)核实 `-fsanitize=address`、`undefined`、`alignment` 和 `thread` 等选项。宿主 Linux 上建议两种分开的构建：内存/UB 用 `-g -O1 -fno-omit-frame-pointer -fsanitize=address,undefined`；并发阶段另建 `-fsanitize=thread`。不要把 ASan 与 TSan 放同一可执行文件；目标平台支持情况查实际工具链。Sanitizer 不保证发现所有错误，不证明真实硬件访存合法。

每周至少留下一组“故意损坏输入→工具定位→修复→相同输入通过”的证据。没有触发运行路径的代码，不能用无报告证明安全。
