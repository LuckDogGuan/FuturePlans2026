## 必须纠偏或保留疑问的技术点

### C01：对齐不是“现代 CPU 已经不要求了”

对应 E10。必须分清 C 对象对齐、指令访问对齐、总线/设备要求与跨 cache line/page 的影响。Armv8-A 的 Normal 与 Device 内存规则不同，Device 非对齐访问可触发 alignment fault；Normal 也受控制位等条件影响。[Arm 官方《Armv8-A memory model》§12.1 Alignment，PDF 第 24 页](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/Armv8-A%20memory%20model%20guide.pdf?revision=58b1dd0a-3800-4218-b21a-f95a0332034c)

RISC-V 自然对齐的 load/store 有保证；非对齐访问行为依执行环境，可能成功、陷阱或 access fault；即便成功，也不能直接推断性能和原子性。[RISC-V 官方 RV32I §1.1.6 Load and Store Instructions](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html#_load_and_store_instructions)

实验结论写成“在 CPU X、内存类型 Y、编译选项 Z 下观察到……”，不得推广为所有 Arm/RISC-V。Linux 侧另看[内核 Unaligned Memory Accesses](https://www.kernel.org/doc/html/latest/core-api/unaligned-memory-access.html)。

### C02：位域字段小，不代表总线只访问一个 bit

对应 E09。编译器可能生成宽读、掩码、读改写；声明 `uint8_t` 风格字段也不能只凭源码猜访问宽度。GCC 明确提示 volatile 位域可能隐式读取，且不适宜直接用于硬件访问。[GCC 官方 When is a Volatile Object Accessed?](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)

因此保留位域作为布局/编译器学习对象；实际 MMIO 先按 IP 手册规定的宽度与内核 I/O API 做显式掩码访问。W1C、read-clear、FIFO 等寄存器必须单独分析副作用；不得对所有寄存器机械套读改写。

### C03：任务调度、CPU 流水线和多核并行是不同层次

对应 BV1PCbP6hEXF 00:49–01:29。保留“追源码而不是信口号”，不采纳 Linux/RTOS 差别只有频率、CPU 普遍必须等一条指令完成才下一条的解释。Arm 官方区分“看起来按程序顺序执行”的概念模型与内部流水线、重排、多发射；不能拿概念模型推导内部时序。[Arm 官方 memory model §4，PDF 第 10 页](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/Armv8-A%20memory%20model%20guide.pdf?revision=58b1dd0a-3800-4218-b21a-f95a0332034c)

FreeRTOS 的默认单核策略涉及固定优先级、抢占和同优先级轮转；SMP 可以在多核同时运行多个任务。对比 Linux 时还要看调度策略、阻塞/唤醒、优先级、实时性目标和配置。[FreeRTOS 官方 Task scheduling](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/01-Tasks-and-co-routines/04-Task-scheduling)

### C04：volatile、锁、内存屏障、设备通知不能互相替代

这是从 E04/E09/E21 引出的学习补充，不假称字幕讲过。GCC 文档说明 volatile 不为普通非 volatile 访问提供内存屏障；系统层还要按内核原语处理 CPU、缓存、DMA 和 MMIO 的可见性与顺序。[GCC Volatiles](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)、[Linux kernel memory barriers](https://www.kernel.org/doc/html/latest/core-api/wrappers/memory-barriers.html)

### C05：QEMU 是可复现验证工具，但要写明模型边界

对应 E14/E19。官方支持通过 gdbstub 停机、看寄存器/内存、断点和观察点。`-s` 与 `-S` 含义不同；单步默认可屏蔽 IRQ/计时器服务，对中断调试现象有影响。使用前固定版本、machine、CPU、镜像/源码和启动参数。[QEMU 官方 GDB usage](https://www.qemu.org/docs/master/system/gdb.html)

### C06：名词识别与授权解释不能靠猜

BV1PCbP6hEXF 03:15–04:23 的 `ZF/ZIER` 按语境疑似 Zephyr，但未核原音，不能编出准确课程章节。BV1gJ4Q6vEnM 04:58–06:12 关于 RISC-V 开放性、Arm 授权和所有权的说法仅为口述，不能替代相应规范和法律条款。本轮不从中推导“所有实现都无商业协议限制”。

`学习注意.md` 写 `PWN`、`uart寄存器 16050`。GPIO/PWM 的方向明确；`16050` 可能想指 16550，尚无原始硬件型号支持。后续实验如果选 NS16550 兼容 UART，需明确它是规划选型，查具体平台手册；不得把 i.MX6ULL UART 自动当成 16550。

## 不可从这些字幕推出的结论

不能推出讲述者技术主张全部正确、薪资叙事代表总体市场、学历门槛不重要、芯片原厂一定双休或无需加班、学完这些就能胜任安全关键软件。字幕提到的百分比、薪资上限/下限、跳槽增幅不进入验收标准。真正可用的是问题意识和验证方法。
