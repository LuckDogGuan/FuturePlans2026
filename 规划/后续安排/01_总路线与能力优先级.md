# 总路线与能力优先级

## 要成为哪一类工程师

主线是 SoC 平台软件、BSP/驱动和芯片诊断。当前设备应用和 C++ 工程经验作为入口，逐步向寄存器、启动、异常、内存和总线下钻。GPU/NPU Runtime 是后续可选岗位族，不是做完 UART 自动晋升的下一站。

严格体现在证据：你应能解释一块内存是谁分配的、哪个上下文改它、设备何时能看见、异常后谁释放、怎样证明没有越界和竞态。不是要求背下所有指令和全部内核源码。

## 20/80 怎么用

“20%”是本次取舍方法，不是经过统计的效果比例。先把反复决定正确性的能力练扎实。

| 优先级 | 内容 | 为什么与工作有关 | 首次重点周 |
|---|---|---|---|
| P0 | 整数提升、符号、字符/字节、位运算、长度与边界 | 传感器有符号值、许可字段、寄存器控制、二进制记录 | W01～02 |
| P0 | 一级/二级指针、数组、生命周期、所有权 | SDK 输出参数、缓冲区、对象释放、异步任务 | W03～06 |
| P0 | struct/union/位域、padding、对齐、端序、访问宽度 | 帧格式、寄存器、DMA 描述符；布局错误可能改变每一个比特 | W05～07、W29 |
| P0 | GDB、ELF、反汇编、故障最小复现、编译器诊断 | 从“应用卡了”变成可定位的证据 | W01起，W07～10集中 |
| P0 | GPIO/PWM/时钟/pinctrl/设备树与驱动模型 | 当前背光、按键、板端状态最容易建立可见闭环 | W11～13 |

## 平台不能混为一谈

| 平台 | 用来证明什么 | 不应据此证明什么 |
|---|---|---|
| 主机 x86-64 用户态 | C语义、内存诊断、协议和并发 | ARM设备内存、真实外设电气行为 |
| i.MX6ULL Pro / Cortex-A7 / ARMv7-A | 实板GPIO/PWM/I2C/SPI、Linux驱动和32位ARM ABI | ARMv8 AArch64、PCIe RC/EP、GPU软件 |
| QEMU AArch64 `virt` | 64位启动、异常、MMU和虚拟平台驱动 | i.MX6ULL寄存器映射、真实上电/信号完整性 |
| QEMU RISC-V `virt` / xv6 | RV64指令/CSR/trap/调度/虚拟设备 | 所有RISC-V扩展、商业SoC全部外设 |
| QEMU PCI EDU | BAR/MMIO/IRQ/DMA驱动生命周期 | PCIe物理链路训练、真实IOMMU隔离和板级时序 |

跨平台迁移时保留算法、格式定义与测试向量；重新核对 ABI、字宽、端序、对齐、异常、内存属性、屏障、IRQ 控制器和设备资源。不能只换编译器。

## 难度怎样增加

先预测单个字节的结果 → 验证对象与地址 → 复现内存错误 → 管理一个外设 → 处理中断与并发 → 跨指令集解释执行 → 协调CPU/设备内存 → 处理设备移除与系统恢复。每一步都有故障注入和退出条件，不能用一段正常打印代替验收。
