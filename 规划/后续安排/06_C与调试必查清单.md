# C与调试必查清单

这是贯穿全部学习周的验收卡，不是额外一门课程。每个题目必须能给出一段可运行反例、规范/手册依据和修正。

## 字节、字符、每一个比特

- `char`不保证有符号；`sizeof(char)==1`不等于ISO C保证所有机器8位字节。本路线目标机器用`CHAR_BIT`确认8位。`uint8_t`等精确宽度类型仅在实现提供时存在。
- 区分字符`'0'`、数值0、字节`0x00`和字符串终止符；字符串长度不包含终止符，二进制数据不可用`strlen`推长度。中文UTF-8一个可见字符可能占多个字节。
- `getchar/fgetc`用`int`接收，先比较EOF；`ctype`参数先转`unsigned char`（或EOF）。逐字节打印偏移、十六进制、可打印表示。
- 构造位掩码前确认操作数宽度，移位量不能为负或达到类型宽度；处理整数提升、`~`后类型、带符号溢出和右移语义。C11/C17下不把负数右移当跨平台保证。
- 用两个字节组装传感器原始值，明确端序、有符号解释、比例和单位。CRC覆盖哪个区间、是否含帧头、初始化值/多项式/反射等须有协议来源；不能自己挑一个CRC算法冒充现有仪器协议。

## 指针、二级指针、结构体

- 为`T*`、`T**`、`T (*)[N]`、`T *[N]`、函数指针分别画对象图；二维数组不是`T**`。`sizeof`数组与形参退化要实测。
- 能区分`const T*`与`T* const`。传二级指针是为了改调用者指针时，失败路径必须约定输出值、所有权与清理责任。
- 指针运算只在同一数组对象及末尾后一位允许范围内；末尾后一位不能解引用。地址数值看起来连续不等于任意跨对象减法合法。
- 每块内存标记分配者、长度、容量、可写性、生命周期、释放者。`realloc`先存临时指针；乘法求分配大小先判溢出。
- `struct`用`offsetof/sizeof/_Alignof`测布局，尾部也可能有padding。不能用`memcmp`比较所有结构体的逻辑相等，不能把结构体裸内存作为稳定跨端协议。
- `union`表示共享存储，不是所有类型互读都可移植。类型重解释要核C语义、对象表示和目标实现，优先`memcpy`或显式字节编码。
- 位域的布局/顺序/可用类型受实现限制；不能对位域取地址。寄存器和协议优先显式掩码/移位，不把C位域布局等同硬件手册。

## 访问宽度、寻址、对齐

在Arm语境，byte=8位、halfword=16位、word=32位、doubleword=64位；64位机器不意味着Arm手册中的word变64位。C的`short/int/long/void*`宽度由ABI与实现决定。

必须区分：对象的对齐要求、指令是否允许未对齐、内存区域属性、操作系统是否修复/拒绝，以及性能成本。把`buf+1`强转为`uint32_t*`不因x86一次跑通就合法；`packed`也不会自动让所有取址/访问安全。

CPU虚拟地址、CPU物理地址、MMIO映射地址、设备总线/DMA地址分别画图。用户态普通指针不能代替`dma_addr_t`，`virt_to_phys`不是通用DMA映射接口。

## SIGBUS、SIGSEGV与GDB

`SIGBUS`不是“所有未对齐访问都会出现”的证明。Linux可以通过映射文件截断后的越界页访问构造较稳定的SIGBUS复现；这个实验说明映射问题，不能冒充CPU对齐fault。架构对齐fault要另记CPU、指令、内存属性和异常现场。[Linux signal说明](https://man7.org/linux/man-pages/man7/signal.7.html)、[mmap说明](https://man7.org/linux/man-pages/man2/mmap.2.html)。

定位顺序：保存输入与编译版本 → 最小复现 → 确认线程/进程与信号（GDB可看`$_siginfo`） → `bt full`/frame → `info registers` → `x/32bx`与对象范围 → `disassemble /s`核源码与访问指令，`/r`看机器码 → 根据来源修正 → 运行失败向量回归。相关命令查[GDB官方手册](https://sourceware.org/gdb/current/onlinedocs/gdb.html/)。

主机练习建议分别构建：调试`-std=c11 -g3 -Og -Wall -Wextra -Wconversion -Wshadow -Wformat=2`；ASan/UBSan`-fsanitize=address,undefined -fno-omit-frame-pointer`；并发另构建TSan，不把ASan和TSan强行合并。警告按实际修正，不用强转或关闭警告掩盖问题。[GCC instrumentation官方文档](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html)。内核练习使用对应内核调试机制，不把用户态Sanitizer命令直接套内核。

## MMIO与并发

`volatile`不等于原子、互斥、内存屏障、DMA一致性或线程安全。Linux MMIO使用对应accessor和映射API；读写寄存器前核宽度、端序、RW/RO/W1C/读清零/保留位。W1C不能无脑读改写；对寄存器的额外一次读也可能改变硬件状态。

规范定位：[WG14 N1570公开草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) 6.2.4生命周期、6.2.8对齐、6.3.1整数提升、6.5有效类型/表达式、6.5.6指针运算、6.5.7移位、6.7.2.1结构体/union/位域、6.7.3限定符、6.7.6声明、7.22.3内存分配。它是C11草案，不是最新版正式标准，也不是入门课。
