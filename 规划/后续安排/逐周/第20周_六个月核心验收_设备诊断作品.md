# 第20学习周：六个月核心验收：设备诊断作品

参考日期：2027-04-19～2027-04-25（北京时间）。核心段。实际执行前核对[假期日历](../02_日历与中国假期.md)；正式调休或公司加班与本周冲突时整周顺延，不在假期补课。状态：未开始。

## 工作问题与门槛

把基础落成自己可接管的作品，而不是再添一串课程名。

先修：上一学习周的必过项有源码、输入与调试证据；失败项未解决先重复上一周。 本周重要性：P0：C正确性、设备路径、故障分层、系统退出、版本复现；首次完整作品与岗位能力对照。

## 精确选课与官方阅读

视频主看/补看：不增加新课。回查[O01 蒋炎岩OS2024视频/讲义](https://jyywiki.cn/OS/2024/)第26～27讲输入输出/驱动、[野火官方驱动视频](https://www.bilibili.com/video/BV1pf4y1974n/)相关专题；按失败项点看。

文字与源码：本计划04阶段门槛、05项目任务和06必查清单；锁定所用内核/工具版本的官方资料，不用master结果冒充旧BSP。

视频建议合计1～2小时，必要补看到3小时须挤掉选做，不挤编码。课程章节与手册章节分开，跨年MIT课程不要混编号。资料核验与播放/字幕限制见[课程表](../资料/01_C与系统课程章节核查.md)和[硬件架构表](../资料/02_外设架构QEMU与PCIe核查.md)。

## 每天做什么：正常周15小时

| 时间 | 具体动作与产物 |
|---|---|
| 周一 2h | 先写本周问题的预期图/表，再看指定视频、查手册。标出数据来源、控制/通知来源、对象或资源的归属。不能只抄笔记。 |
| 周二 2h | 整合字节解析、GPIO/PWM或一个可用外设、事件队列与CLI，功能范围先冻结 |
| 周三 2h | 自选一个过去靠AI的模块，独立解释并修改边界，记录本人贡献 |
| 周四 2h | 在干净目录复现构建与实验，形成第一版README/故障报告/版本和回退说明。 |
| 周五 2h | 开始故障注入：盲测3个未知故障，至少各来自C内存、外设路径、并发退出；没有硬件波形的项明确未验，不能用模拟补写。 |
| 周六 5h | 2h定位/修复，2h正常与失败回归，1h闭卷解释和填写周报。没做完顺延，选做首先删减。 |
| 周日 | 休息，无看课和补债要求。 |

## 本周必过项

五项关键维度全部通过，能演示真实工作问题如何被底层证据定位；发布前审查授权/脱敏，仅本地准备，不自动上传GitHub。

验收同时检查：功能正确、机制解释、独立实现、故障定位、他人可复现。可查手册，不能现场复制生成答案。至少一个30～60行或等价小任务由本人从空白完成，解释每个长度、指针、状态位和失败分支。

## 要留下的文件

在实验仓库的`evidence/W20/`保存：输入与预期、源码版本/构建命令、实际结果、一次故障的现场/根因/修复前后、三张图（数据/通知/资源），以及`周报.md`。临时故障样例独立存放，不污染工作产品。周报写清哪些由本人完成、哪些来自AI，以及模拟/板端软件/波形分别过了什么。

选看与延期：P1：此时可开始搜BSP/平台软件/诊断岗位要求做差距复核；工资与录用不作承诺。
