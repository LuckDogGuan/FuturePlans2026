# 第39学习周：作品整理：可复现版本与贡献边界

参考日期：2027-10-11～2027-10-17（北京时间）。后续深化段。实际执行前核对[假期日历](../02_日历与中国假期.md)；正式调休或公司加班与本周冲突时整周顺延，不在假期补课。状态：未开始。

## 工作问题与门槛

陌生工程师拿到作品，能否独立构建、复现实验并看懂你真正解决的底层问题？

先修：上一学习周的必过项有源码、输入与调试证据；失败项未解决先重复上一周。 本周重要性：P0：可复现工具链/源码commit/镜像版本、构建入口、输入与失败案例、最小接口、许可与脱敏、本人/第三方/AI贡献、回退标签。

## 精确选课与官方阅读

视频主看/补看：不增加新课，不要求重复前38周视频。需要视频表达可检索“Linux Foundation technical demo reproducible bug report”，本轮未核实精确讲次。只录制本人的5～8分钟演示作为可选产物，不用剪辑替代代码证据。

文字与源码：按作品实际范围回查[QEMU EDU规格](https://www.qemu.org/docs/master/specs/edu.html)寄存器/DMA协议、[Linux DMA API](https://docs.kernel.org/core-api/dma-api-howto.html)所有权、[QEMU GDB](https://www.qemu.org/docs/master/system/gdb.html)调试方法。依赖与许可证以锁定版本的上游README/LICENSE为准，工作项目商业代码/真实人员数据不能自动公开。

视频建议合计1～2小时，必要补看到3小时须挤掉选做，不挤编码。课程章节与手册章节分开，跨年MIT课程不要混编号。资料核验与播放/字幕限制见[课程表](../资料/01_C与系统课程章节核查.md)和[硬件架构表](../资料/02_外设架构QEMU与PCIe核查.md)。

## 每天做什么：正常周15小时

| 时间 | 具体动作与产物 |
|---|---|
| 周一 2h | 先写本周问题的预期图/表，再看指定视频、查手册。标出数据来源、控制/通知来源、对象或资源的归属。不能只抄笔记。 |
| 周二 2h | 选一个主作品冻结范围为字节核心+外设或EDU驱动+诊断CLI，整理复现命令和版本清单，不拼成巨型平台 |
| 周三 2h | 本人在干净新目录完成一次构建/运行/故障复现，把缺失依赖和隐含步骤补入README |
| 周四 2h | 生成本地release包和hash，记录恢复到前版步骤，画端到端数据/通知/资源三图，写贡献表和已知限制。 |
| 周五 2h | 开始故障注入：让第二人或独立环境按README复现一项故障，检查相对路径、缺依赖、旧DTB与错误版本。没有第二人时用干净环境并明确自验，不冒称他人复现。 |
| 周六 5h | 2h定位/修复，2h正常与失败回归，1h闭卷解释和填写周报。没做完顺延，选做首先删减。 |
| 周日 | 休息，无看课和补债要求。 |

## 本周必过项

一个命令入口能复现既定演示，包/源码/证据版本一致。能解释30～60行本人核心修改，报告许可和未验项。本周只本地准备，公开上传/发帖另由用户决定。

验收同时检查：功能正确、机制解释、独立实现、故障定位、他人可复现。可查手册，不能现场复制生成答案。至少一个30～60行或等价小任务由本人从空白完成，解释每个长度、指针、状态位和失败分支。

## 要留下的文件

在实验仓库的`evidence/W39/`保存：输入与预期、源码版本/构建命令、实际结果、一次故障的现场/根因/修复前后、三张图（数据/通知/资源），以及`周报.md`。临时故障样例独立存放，不污染工作产品。周报写清哪些由本人完成、哪些来自AI，以及模拟/板端软件/波形分别过了什么。

选看与延期：P1：整理针对BSP/平台软件/芯片验证软件的简历证据。P2：为作品新增Web平台、重写现有稳定驱动。
