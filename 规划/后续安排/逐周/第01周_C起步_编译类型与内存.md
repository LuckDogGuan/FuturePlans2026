## 工作问题与门槛

板端同一个值为什么在日志、内存和上位机里看起来不同？先建立可信的C实验环境。

先修：完成W01前环境准备并确认独立实验目录；无需先刷课。 本周重要性：P0：预处理/编译/汇编/链接；变量、基本语句、函数原型；sizeof/CHAR_BIT；栈/静态存储与对象生命周期。

## 每天做什么：正常周15小时

| 时间 | 具体动作与产物 |
|---|---|
| 周一 2h | 先写本周问题的预期图/表，再看指定视频、查手册。标出数据来源、控制/通知来源、对象或资源的归属。不能只抄笔记。 |
| 周二 2h | 建立独立host实验目录，记录gcc/gdb版本，用-E/-S/-c保存中间产物 |
| 周三 2h | 写type_report输出类型宽度、地址和十六进制，预测再运行 |
| 周四 2h | 用GDB断点观察局部变量，生成一张对象/值/地址对照表。 |
| 周五 2h | 开始故障注入：故意漏声明函数或printf格式错配，在编译阶段识别；再加入一个循环边界错误，用断点观察第一次偏离预期的位置。 |
| 周六 5h | 2h定位/修复，2h正常与失败回归，1h闭卷解释和填写周报。没做完顺延，选做首先删减。 |
| 周日 | 休息，无看课和补债要求。 |

## 本周必过项

从空白编译一个含函数和数组的程序，解释四个构建阶段；宽度表有主机结果，ARM列先标待测，不猜；能定位而非仅删除警告。

验收同时检查：功能正确、机制解释、独立实现、故障定位、他人可复现。可查手册，不能现场复制生成答案。至少一个30～60行或等价小任务由本人从空白完成，解释每个长度、指针、状态位和失败分支。

## 要留下的文件

在实验仓库的`evidence/W01/`保存：输入与预期、源码版本/构建命令、实际结果、一次故障的现场/根因/修复前后、三张图（数据/通知/资源），以及`周报.md`。临时故障样例独立存放，不污染工作产品。周报写清哪些由本人完成、哪些来自AI，以及模拟/板端软件/波形分别过了什么。
