# 第40学习周：闭卷综合验收：长期分支与晋级

参考日期：2027-10-18～2027-10-24（北京时间）。后续深化段。实际执行前核对[假期日历](../02_日历与中国假期.md)；正式调休或公司加班与本周冲突时整周顺延，不在假期补课。状态：未开始。

## 工作问题与门槛

在陌生坏数据、通知丢失和生命周期错误同时出现时，能否独立给出可验证的根因与修复？下一阶段按证据缺口排。

先修：上一学习周的必过项有源码、输入与调试证据；失败项未解决先重复上一周。 本周重要性：P0：C与位级解析、ABI/地址、外设或PCI路径、并发停止、故障定位、复现与回滚。考核覆盖已实作范围，真板未完成项不能用模型代填。

## 精确选课与官方阅读

视频主看/补看：本周不新增视频。只在验收完成后按错题回看相应课程标题，避免考前无边界刷课。W21～39视频与文档入口已经分别给出。

文字与源码：前45分钟闭卷写最小代码与三图，之后可查[QEMU EDU规格](https://www.qemu.org/docs/master/specs/edu.html)/[Linux DMA API](https://docs.kernel.org/core-api/dma-api-howto.html)/[Linux MMIO访问指南](https://docs.kernel.org/driver-api/device-io.html)或实际芯片手册，不能复制现成生成答案。最终报告引用固定版本和实际手册页码，课程观看记录不计通过证据。

视频建议合计1～2小时，必要补看到3小时须挤掉选做，不挤编码。课程章节与手册章节分开，跨年MIT课程不要混编号。资料核验与播放/字幕限制见[课程表](../资料/01_C与系统课程章节核查.md)和[硬件架构表](../资料/02_外设架构QEMU与PCIe核查.md)。

## 每天做什么：正常周15小时

| 时间 | 具体动作与产物 |
|---|---|
| 周一 2h | 先写本周问题的预期图/表，再看指定视频、查手册。标出数据来源、控制/通知来源、对象或资源的归属。不能只抄笔记。 |
| 周二 2h | 从空白独立写显式长度的字节解码或寄存器字段小任务，覆盖二级输出参数/错误契约并逐位解释 |
| 周三 2h | 抽三类未知故障各一项在隔离分支定位，保存现场→最小复现→假设→验证→修复，补端到端数据/通知/资源三图 |
| 周四 2h | 运行核心回归并切回上一稳定版本，按能力缺口选择长期分支：BSP外设深化或PCIe真板或RTOS专线，只选一条先做8周。 |
| 周五 2h | 开始故障注入：出题者只提供故障现象，不先给答案。未知故障至少覆盖布局/长度、通知/超时、所有权/停止三类，测试设备能力不足时改用已完成实验范围的等价案例并标替换。 |
| 周六 5h | 2h定位/修复，2h正常与失败回归，1h闭卷解释和填写周报。没做完顺延，选做首先删减。 |
| 周日 | 休息，无看课和补债要求。 |

## 本周必过项

五维验收：功能、机制解释、独立代码、故障定位、他人可复现均有证据且无关键安全/数据完整性失败。未过项按周返工，不能以“40周结束”自动毕业或保证录用。

验收同时检查：功能正确、机制解释、独立实现、故障定位、他人可复现。可查手册，不能现场复制生成答案。至少一个30～60行或等价小任务由本人从空白完成，解释每个长度、指针、状态位和失败分支。

## 要留下的文件

在实验仓库的`evidence/W40/`保存：输入与预期、源码版本/构建命令、实际结果、一次故障的现场/根因/修复前后、三张图（数据/通知/资源），以及`周报.md`。临时故障样例独立存放，不污染工作产品。周报写清哪些由本人完成、哪些来自AI，以及模拟/板端软件/波形分别过了什么。

选看与延期：后续分支各另开8周任务：BSP看clock/reset/pinctrl/IIO/相机路径，PCIe需先核RC/EP硬件，RTOS看时序预算与端口。工资、芯片设计与完整内核开发不作本计划通过承诺。
