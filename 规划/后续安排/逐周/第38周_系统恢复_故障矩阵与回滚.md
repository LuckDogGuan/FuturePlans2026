# 第38学习周：系统恢复：故障矩阵与回滚

参考日期：2027-09-20～2027-09-26（北京时间）。后续深化段。实际执行前核对[假期日历](../02_日历与中国假期.md)；正式调休或公司加班与本周冲突时整周顺延，不在假期补课。状态：未开始。

## 工作问题与门槛

相机、背光、语音或网络失败时，哪些动作应停止、哪些结果必须保存、何时允许下一轮采集？

先修：上一学习周的必过项有源码、输入与调试证据；失败项未解决先重复上一周。 本周重要性：P0：检测/分层/隔离/恢复状态、幂等、超时、重试上限/退避、保留已完成结果、人工确认再开新采集、版本回滚。只验证实验模型，不顺手改稳定产品。

## 精确选课与官方阅读

视频主看/补看：不增加新大课。按失败点回看[MIT6.1810 2025官方日程](https://pdos.csail.mit.edu/6.1810/2025/schedule.html)LEC18《Crash recovery》中的提交/恢复思路，仅作日志机制启发。[Bootlin公开演讲与录像目录](https://bootlin.com/docs/)检索“Bootlin embedded Linux update rollback recovery”，未核实独立免费视频讲次。

文字与源码：[Linux PCI驱动指南](https://docs.kernel.org/PCI/pci.html)停止资源、[Linux Workqueue](https://docs.kernel.org/core-api/workqueue.html)同步取消作为回调寿命依据。[Linux PCI Error Recovery](https://docs.kernel.org/PCI/pci-error-recovery.html)错误状态与恢复阶段作分层参照。工作板已有update/rollback说明按实际代码版本阅读，不把PCI错误回调直接用作应用恢复框架。

视频建议合计1～2小时，必要补看到3小时须挤掉选做，不挤编码。课程章节与手册章节分开，跨年MIT课程不要混编号。资料核验与播放/字幕限制见[课程表](../资料/01_C与系统课程章节核查.md)和[硬件架构表](../资料/02_外设架构QEMU与PCIe核查.md)。

## 每天做什么：正常周15小时

| 时间 | 具体动作与产物 |
|---|---|
| 周一 2h | 先写本周问题的预期图/表，再看指定视频、查手册。标出数据来源、控制/通知来源、对象或资源的归属。不能只抄笔记。 |
| 周二 2h | 依据现有采集工作流列相机无响应/控制输出失败/语音失败/上传失败/进程重启五项矩阵，定义可恢复与必须人工处理条件 |
| 周三 2h | 本人在独立故障注入器实现IDLE/CAPTURING/SAVED/RECOVERING/WAIT_CONFIRM状态，已保存结果与上传重试独立 |
| 周四 2h | 每类跑正常/失败/恢复序列，画数据保存/故障通知/设备及文件资源三图，演练一次实验版本回退。 |
| 周五 2h | 开始故障注入：注入重复完成、语音报错、上传断线、恢复后晚到回调和半写日志。要求语音失败不阻断已授权采集，恢复后不静默开始下一人拍摄。 |
| 周六 5h | 2h定位/修复，2h正常与失败回归，1h闭卷解释和填写周报。没做完顺延，选做首先删减。 |
| 周日 | 休息，无看课和补债要求。 |

## 本周必过项

五类故障每类有预期、实际、根因和恢复证据，数据不伪造不丢已完成结果。模拟通过与真板可靠性明确分开，线上稳定配置无未经授权变动。

验收同时检查：功能正确、机制解释、独立实现、故障定位、他人可复现。可查手册，不能现场复制生成答案。至少一个30～60行或等价小任务由本人从空白完成，解释每个长度、指针、状态位和失败分支。

## 要留下的文件

在实验仓库的`evidence/W38/`保存：输入与预期、源码版本/构建命令、实际结果、一次故障的现场/根因/修复前后、三张图（数据/通知/资源），以及`周报.md`。临时故障样例独立存放，不污染工作产品。周报写清哪些由本人完成、哪些来自AI，以及模拟/板端软件/波形分别过了什么。

选看与延期：P1：真实20轮/20分钟边界以后单独安排并写明要求。长期soak另行定义，有限模拟不得外推为已通过。
