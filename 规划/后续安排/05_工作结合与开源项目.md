# 工作结合与开源项目

## 同一个实验台逐步下钻

项目暂名 `device-lab`，这里只给设计与任务，不在本轮创建或改生产项目。功能是采集/模拟设备事件、控制输出、记录时序、注入故障并恢复。先做CLI，不增加Qt/Flutter界面专项负担。

| 当前工作场景 | 实验台任务 | 最终应解释的底层问题 |
|---|---|---|
| 脊柱仪器正负读数、缺测、数据帧 | 手写字节解码、显式格式、边界拒绝 | 位宽、符号扩展、单位、格式与C对象布局 |
| 背光与按键 | GPIO/PWM、事件时间戳与去抖 | pinmux、clock、polarity、IRQ、上层状态 |
| 拍摄、语音、上传不能互相卡死 | 有界队列、工作线程/进程、超时与停止 | 阻塞、调度、信号、锁、竞态和背压 |
| 设备断连/服务失败/恢复 | 事件状态机与分类错误 | 真实设备状态、软件返回值和业务状态的分层 |
| SDK返回内存、相机帧缓冲 | owner/borrowed、二级指针、回调与释放 | 生命周期、异步完成、UAF、缓存/DMA后续延伸 |
| Wi-Fi更新与版本回退 | 学习包版本、校验与恢复清单 | 交付可追溯性；不是从课程推定已会安全升级 |
| 旧UMIC串口/CAN流程 | 只读梳理已有接口边界，再做公开模拟器 | 厂商API调用与自己完成驱动的区别 |

真实源码入口可先按文件名定位：既有核查提到`runtime_v3.c`、`upload.c`、`luckfox_camera.c`，但那是历史快照。真正练习时先检查仓库版本、AGENTS、GitNexus与实际函数，再写证据。不要固定依赖旧行号。

## 建议目录

```text
device-lab/
  core/           # C字节解析、数据结构、状态机，尽量可跨平台
  host/           # CLI、模拟设备、故障重放
  board/          # i.MX6ULL实验配置与独立驱动
  qemu/           # AArch64、RV64、PCI EDU，分别记录命令和版本
  tests/          # 已知向量、边界、失败注入，不追求无意义覆盖数字
  docs/           # 寄存器表、地址图、时序图、实验与复盘
  evidence/       # 脱敏日志、版本、波形/截图、结果与限制
```

每周继承之前核心模块；错误定位应有最小独立样例，不能只在大工程里加日志猜测。用户态和内核代码明确分开，不能把libc/malloc直接搬进内核。

代码质量按“正确与安全→易维护→易读→有测量再优化”推进。先修边界、寿命和失败行为，再整理接口；C++/Flutter只随工作补缺口，不另开第二套必修课。

## 仪器与硬件使用

W11前确认板卡版本、排针定义、供电、电平与共地，再接线；具体探头设置和量程以设备说明书为准。GPIO/PWM用波形证据闭环；I2C/SPI/UART同时保存逻辑分析仪解码与原始时序。读回寄存器、驱动返回成功和实际光亮/波形分别记录。

无需现在采购。W14/W15缺传感器时先跑控制器/模拟路径，并把真实总线验收保留；进入实作前再按电平、接口、驱动资料和预算选一个器件。i.MX6ULL不承担PCIe硬件验收，W33后确有岗位/实验需求才评估支持RC/EP的平台。

## 独立能力与AI

周一先手写预期与数据/信号路径；核心题先独立做45～90分钟，再向AI索要提示或评审。每周记录“本人设计/本人实现/AI生成/本人已解释并修改”。AI可以查资料、生成样例，但验收时要关闭答案，口述故障根因并做一次条件变化。

## 开源交付

只发布自己有权公开的独立实验代码、公开手册链接、合成测试数据。工作项目源码、真实学生/患者记录、设备标识和公司内部资料不直接搬进公开仓库。保留课程/上游代码许可证与修改说明。

W20形成第一个可展示版本；W40形成完整作品。发布前本地完成README、架构图、重现命令、失败样例、结果与限制、许可证、版本标签方案和回退说明。**本次仅规划，不自动上传、发布或推送GitHub。**
